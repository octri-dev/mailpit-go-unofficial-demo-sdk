## Quickstart

The no-auth example calls `getChaos` (GET `/api/v1/chaos`), an eligible operation that requires no authentication credentials.

```go
package main

import (
	"context"
	"fmt"

	sdk "github.com/octri-dev/mailpit-go-unofficial-demo-sdk"
)

func main() {
	ctx := context.Background()
	config := sdk.ClientConfig{BaseURL: "http://localhost:8025"}
	sdk.Configure(&config)
	result, err := sdk.GetChaos(ctx, config)
	if err != nil {
		panic(err)
	}
	fmt.Printf("%+v\n", result)
}
```

## Authentication

This build disables generated authentication. Eligible operations send no authentication credentials; use `ClientAuthConfig.Headers` only for explicit service-specific headers.

## Client behavior

- Base URL: set it in `ClientConfig` before the first request.
- Transport: net/http.
- Timeout: 30,000 ms per attempt.
- Retries: up to 3 attempts for status codes `408`, `425`, `429`, `500`, `502`, `503`, `504`, with 500–8,000 ms backoff.
- Idempotency: enabled for `POST`, `PATCH` using `Idempotency-Key`.
- Error telemetry is disabled by default, and this build carries no reporting endpoint: opting in sends nothing unless you also set an endpoint in the logging config.
- Telemetry PII filtering is enabled by default: common credentials and direct identifiers are recursively replaced with `[REDACTED]` before reports are sent, matched as whole keys (`api_key`, `email`) and as words inside longer keys (`billingEmail`, `customer_phone_number`). Disable it only through the generated logging config's `filterPii` (or language-native equivalent) for a trusted private sink.

### What telemetry contains

If you enable telemetry, a failed request reports the operation name, HTTP method and path (no query string), status code, request id, the error class, message and stack, and the environment and release you configure. Request and response bodies, headers, cookies and the caller's IP address are never included. A user object, device or page context, and breadcrumbs are sent only after your application grants consent (where the runtime has a consent switch) or sets them explicitly. Reports go to the API provider's monitoring project; you are responsible for telling your own users about this in the same way you would for any error-reporting tool, and for enabling it only where you have a lawful basis to do so.

High-level operation methods return the typed response body directly. The low-level request layer returns an `SdkResponse<T>` envelope containing data, status, headers, request ID, latency, and attempt count.

## Errors and response metadata

All failure paths use a small, predictable hierarchy:

| Error | Meaning |
| --- | --- |
| `SdkValidationError` | A request argument failed an OpenAPI constraint before network I/O. |
| `SdkHttpError` | The server returned a non-2xx response. |
| `SdkNetworkError` | DNS, connection, TLS, or socket failure. |
| `SdkTimeoutError` | The configured per-attempt timeout elapsed. |

HTTP errors expose `StatusCode`, the response body and headers, plus `RequestID` when the server supplies one. Preserve the request ID in support logs; it is the fastest way to correlate a failed SDK call with server-side traces.

## Project layout and API discovery

- Operation implementations are grouped under root-level namespace `.go` files.
- 19 component models are split by API domain under root-level `models_<domain>.go` or `models_<tag_path>_models.go` files in the same public `sdk` package.
- Component schemas can choose a nested model folder with `x-octri-sdk-tags: ["Billing/Invoices"]`; the first tag owns the model and `/` creates nesting.
- [`sdk-manifest.json`](sdk-manifest.json) is the language-neutral public API index: operations, request/response modes, model properties, enum values, and generation settings.
- Public barrel/module exports are the compatibility boundary. Import public model names from those exports; internal domain filenames may evolve without changing model names.
